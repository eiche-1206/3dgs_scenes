## 命名规范

```
15f_<面数>_<图集>_g<geom数>_<光照>[_<改动>]

面数   350k 391k 450k 636k 991k 1185k 1461k 1954k
图集   4k / 8k
geom   g01（单 geom）/ g30 / g48
光照   flat  = headlight ambient 1.0 / diffuse 0     ← 基线
       dif15 = ambient 0.8 / diffuse 0.15
改动   maxcov / amb90 / amb110 / msaa8 / taubin10 / uniform ...
```

`uniform` 表示均匀抽面（无分级），不带则为四档优先级分级。

**改名时必须同步改 scene.xml 里的绝对路径**，`texturedir` 没有末尾斜杠，用
`s|/variants/vX/|...|` 这种带斜杠的模式会漏掉它 —— 见文末「踩过的坑」第 2 条。

## 影响渲染的因子（全部经单变量对照）

| 因子 | 影响 | 该取什么 | 证据 |
|---|---|---|---|
| **头灯 diffuse** | 决定性 | **0** | 同 349k 网格同图集，仅改 diffuse：0.15→0，消防门锐度 23.8→29.0 |
| **图集分辨率** | 决定性 | **8192** | 1.19M 面上 4096 让纹素密度 0.70→1.42 cm，肉眼可见糊 |
| **纹素密度** | 决定性 | **≤0.8 cm/纹素** | 图集与面数的合成量，才是真正判据 |
| 贴图烘焙方式 | 大 | 渲染烘焙 | KD 树取色 → 多视角渲染投影，平面区域锐度 5.58→7.14（gsplat 上限 7.40） |
| 面数 | 中 | 越高越好 | 头灯统一后 349k→1.95M 锐度单调上升 29.0→37.0，13 机位无一例外 |
| geom 数（分块） | 仅影响性能 | 拆开 | 画质逐像素无损（差 0.005/255）；636k 单 geom 19.83 ms → 30 geom 1.10 ms |
| 抽面分级 | 小但免费 | 四档优先级 | 同 383k 预算下前台锐度 18.39→20.26 |
| 贴图覆盖率 | 无 | — | 75.3%→80.6% 锐度 29.0→28.8 |
| ambient 曝光 | 无 | 1.0 | 0.9/1.0/1.15 只是亮度平移 |
| MSAA | 无 | 默认 4 | offsamples 4→8 指标反降（边缘更平滑） |
| TSDF 体素 | 未触及 | 2 cm 够用 | 稠密网格三角形边长 2.17 cm 是上限，1.95M 面才用到 5.8 cm |

### 头灯为什么是决定性的

`bake_texture_render.py` 把 gsplat 渲出的**带光照**颜色写进了 albedo。MuJoCo 的方向光
再打一遍，等于在已有明暗上又叠一层，把对比度冲平。

| headlight | 亮度 | 锐度 |
|---|---|---|
| amb .35 / dif .40（MuJoCo 默认） | 72.3 | 19.57 |
| amb .12 / dif .15 | 36.2 | 5.55 |
| amb .80 / dif .15 | 113.2 | 41.78 |
| **amb 1.0 / dif 0** | 125.3 | **51.94** |

方向是**拿掉方向光、环境光拉满**，不是整体调暗 —— 调暗会把细节埋进阴影。

### 分块为什么能让面数几乎免费

MuJoCo 按 geom 做视锥剔除。整栋楼装进一个 geom 时，相机朝哪都要画完整栋。

```
636,306 面, 1 个 geom     19.83 ms    50 fps
636,306 面, 4 个 geom      1.59 ms   628 fps    ← 只切 4 块就够
636,306 面, 30 个 geom     1.27 ms   785 fps
1,954,209 面, 48 个 geom   0.91 ms  1102 fps    ← 面数 3 倍，比单 geom 快 20 倍
```

按面心分块，每个面只属于一块，无重叠无空隙。

## 机位

**机位必须先侦察再定，不能照平面图估坐标。** 估出来的机位会对着墙和空地。

侦察方法：用颜色/几何特征在高斯里聚类找候选（大片白色立面找柜体、墙面高度密集彩色找
展板、高饱和绿色找 EXIT 灯牌），每个候选四个方向各渲一张，从实际看得见的东西里挑框。

参考截图在 `15F/tmp/`（11 张，来自交互式 viewer），是机位质量的标准。

> **自动反解位姿失败了。** 试过粗网格搜索 + 降采样颜色直方图打分，误差 24–62，且多张
> 不同截图匹配到同一位姿 —— 在一栋处处是白墙的楼里，这个特征没有分辨力。渲出来验证，
> 右侧全是墙面和空地。要做只能上真正的图像特征匹配（SIFT/LoFTR）。

## 踩过的坑

### 1. 三条 MuJoCo SDF 静默失败铁律

症状统一是：编译通过、无 warning、渲染正常、`ncon` 永远 0。

1. SDF geom 必须裹在 `<body>` 里
2. 挂插件的 `<mesh>` 绝不能有 `file=`
3. `<config key="path">` 必须绝对路径

### 2. `texturedir` 没有末尾斜杠

复制变体时用 `s|/variants/vX/|...|` 替换路径，`texturedir="/.../variants/vX"` 不匹配，
结果整个变体一直在读**原变体的图集**。发现方式是两个变体的渲染图 md5 完全相同。
**改用正则 `s#/variants/[A-Za-z0-9_]+#...#g`，并在改完后 grep 校验。**

### 3. XML 注释里的双连字符

`<!-- 编辑这个 -- 不是那个 -->` 是**非法 XML**。MuJoCo 的 tinyxml 容忍，ElementTree 不容忍
—— 任何用标准 XML 工具处理 scene.xml 的下游都会挂，e2e 的 `gt_map_baker` 就是第一个撞上的。

### 4. 三个测量陷阱

| 陷阱 | 后果 |
|---|---|
| **并发污染渲染计时** | 450k 变体测出比 383k 更快，纯因为测 383k 时有 xatlas 在跑。基准必须独占 GPU 串行 |
| **单次 mj_step 计时** | 曾据此报「视觉面数拖慢物理 26%」，改 5 次重复取中位数后不成立 |
| **锐度指标不可信** | 拉普拉斯方差量的是局部对比度，几何噪声和曝光都会拉高它。判断必须以图为准 |

### 5. 参考网格要采样表面而非顶点

281k 面 / 4881 m² 的网格顶点间距 17 cm，查最近顶点量到的是尺子的刻度不是被测物的误差。

## 被推翻的结论（保留，因为容易重犯）

| 曾经的结论 | 实际 | 怎么翻的 |
|---|---|---|
| 「350k 面有渲染断崖，是面数上限」 | 那是**单 geom** 的病态行为 | 拆成 4 块就消失 |
| 「4096 图集无损」 | 只在 450k 面上成立 | 到 1.19M 时纹素密度掉到 1.42 cm，明显糊。**不能跨面数外推** |
| 「面数越高越糊」 | 头灯混淆 | 那些高面数版本用的是 dif 0.15；统一为 flat 后面数越高越清晰 |
| 「视觉面数拖慢物理 26%」 | 测量噪声 | 5 次重复后真实效应 ~8%，且离散度与之同量级 |
| 「GT 图上框是前台」 | 那是**茶水间** | 侦察渲染确认；真前台在左下框 (−16.5, 1.0) |

> 最后一条影响 `decimate_tiered.py` 的 tier-1 区域定义 —— 目前 REGIONS 里 `reception`
> 和 `pantry` 两个框标反了。对变体间对比无影响（同一份网格），但最终交付版要改对。
